# BFSU ClearLens

中文名称：**BFSU 文本整理器**  
版本：**1.5.11**

BFSU ClearLens 是 BFSU LexiScope 框架下的批量文本整理、确定性降噪、编码转换与大模型辅助校对软件。软件只导入文本并输出文本，适用于 OCR 后文本、网页抓取后正文、语料采集结果和人工转写材料。

本软件**不执行 OCR、不抓取网页、不提取元信息**。这些任务由 LexiScope 中的其它工具承担。

## 主要功能

### 文件与批处理

- 导入单个或多个文本文件
- 递归导入文件夹
- 将文件或文件夹拖放到文件队列
- 带序号的文件队列，支持多选删除、清空全部文件并同步重置日志、右键菜单和场景化快捷键
- 文件菜单提供“清空软件（新建整理任务）”，可一次清除文件队列、编辑区、差异、历史、进度和日志，同时保留用户设置及规则
- 规则与大模型均可分别整理当前、选中或全部文件；另有大模型校对当前结果
- 异步扫描和导入、后台规则预览、可取消任务、总体进度显示和多进程/多线程批处理
- 导入或执行任务时，除“中止任务”外的可操作组件及菜单暂时冻结，防止并发任务和误编辑
- 默认并行任务数为当前逻辑处理器数量的一半，可在设置中调整
- 保存、另存为、全部保存；输出目录与源文件目录隔离，顶部工具栏可直接打开输出目录
- 合并选中文件、合并全部文件
- 保留导入文件夹结构，避免同名文件相互覆盖
- CSV / JSON 整理日志导出
- 工具栏实时显示当前文件与全部文件字符数；统计窗口提供字符、字母、数字、标点、符号、行、段落和 UTF-8 字节等指标
- 编辑器字号可通过工具栏、快捷键或设置窗口调整
- 主界面与辅助窗口已迁移到 CustomTkinter；按钮、复选框、输入框、选项卡、文本编辑器、滚动条、进度条和分隔栏使用统一的 ClearLens 视觉主题
- 左侧功能栏初始约占工作区宽度的四分之一，可通过 CustomTkinter 分隔线自由拖动；文件队列初始约占右侧工作区高度的 36%
- Windows 下由 CustomTkinter 自动识别显示缩放并同步调整组件与字体；文件队列、差异表、日志表和大模型建议表使用独立的逐窗口 DPI 适配层
- 分隔栏两侧容器使用明确的实际像素边界，不会被内部组件的请求尺寸压缩到左上角；主界面和嵌套预览区始终填满分配空间
- 主菜单、级联菜单和右键菜单的字体按所属窗口的实际 DPI 设置，与 CustomTkinter 界面字号保持一致
- 软件不提供全局界面缩放选项；编辑器文字仍可通过工具栏、快捷键或首选项单独调整
- 原始文档和当前／预览结果显示同步的真实逻辑行号；行号只固定在段落／逻辑行首，不会随自动换行的续行移动，片段视图仍显示其在完整文档中的实际行号
- 每个可勾选功能面板均提供“全选”和“取消全选”
- 当前整理参数、自定义正则和大模型自然语言规则可保存为独立 JSON 整理方案，并可在同类任务中重新导入
- 主工具栏采用两行分区布局，提供“重置当前”“重置全部”；按钮使用紧凑的“当前／全部”术语，避免高缩放窗口中字符统计被挤出
- 状态栏左侧显示当前任务，右侧同时显示总体完成数量、百分比和进度条；大模型请求会持续显示当前片段、等待时长、单次超时阈值以及“已收到响应／本机校验／缩小片段重试”等阶段；任务执行期间界面进入只可中止状态，所有后台任务严格互斥
- 勾选规则和本地整理选项只改变待执行方案，不会自动预览或处理；须点击预览、规则整理或相应大模型按钮才会执行。若勾选了大模型自然语言规则，“预览效果”会在明确的发送确认后生成不写回文件的大模型规则预览
- 人工连续输入只更新当前文件队列行，不再逐字符重建文件树，因此可正常连续录入、粘贴和整体修改
- 所有规则、大模型、转码和人工编辑都以上一次处理后的当前文本为输入，依次叠加
- 处理结果先保留在内存中；仅“保存”“另存为”和“全部保存”写入结果文件
- 保存完成时给出明确提示，未保存状态会在文件队列中标示
- 关闭软件时如有未保存的当前结果，会先显示文件数量并要求确认
- 分隔栏保存相对比例，窗口最大化与恢复时左右、上下区域占比保持不变
- “预览效果”始终固定比较“当前工作文本 → 完整预览结果”，并在后台整理全文后让编辑器显示首处真实差异附近的流畅片段；不会再把本地整理后的中间状态误当作左侧基线，也不会出现“预览样本未命中、正式整理全文却生效”的不一致
- 启用正则规则时，状态栏分别报告启用规则数、实际命中数或“未匹配”，便于确认规则是否工作；正则未命中时，本地选项产生的变化仍会在编辑器中显示
- HTML、XML、压缩 JSON 和其它超长行文件使用延迟选取、超长行识别、最多 1.2 万字符的虚拟化片段、强制无换行及合并式行号重绘；编辑器撤销缓存会在文件切换后重置，规则处理和保存仍使用完整文本
- 非 UTF-8 大文件只用最多 1 MiB 样本进行编码候选排序，再对最终候选严格解码完整文件，避免为每个候选反复扫描整份大文件
- 大文本差异比较具有相同文本快速路径、大型行集优化与显示数量保护；整理日志采用增量追加，避免批量处理中反复重建整表

### 操作历史

- 编辑菜单提供撤回、重做、当前文件恢复原文、选中文件恢复原文和全部文件恢复原文
- 规则整理、大模型整理、大模型校对建议、自然语言规则和人工编辑均进入统一历史
- 一次批处理作为一个历史项，可同时撤回或重做多个文件
- 最近保存 50 项操作，历史文本采用快速压缩，降低大文件的内存开销
- 整理日志采用带时间戳的表格；可从日志撤销最新的可撤销文本操作，原日志随后冻结，并新增一条撤销记录

### 确定性文本整理

- 换行符、BOM、Unicode 规范化；Unicode 字形处理需通过独立复选框启用
- 控制字符、零宽字符、双向控制字符、私用区字符处理
- Emoji 表情符号处理
- ftfy 乱码修复
- HTML 实体还原
- JavaScript、CSS、`noscript`、`template` 等网页代码块处理
- 行首空白、行尾空白、重复空格、制表符规范化
- 汉字间异常空格处理
- 全角转半角、半角转全角（独立启用复选框）
- 繁体转简体、简体转繁体（独立启用复选框）
- 中文标点与半角标点转换（独立启用复选框）
- 空行删除、连续空行合并、文末换行补齐；能识别 `&nbsp;`、`<br>`、HTML 注释和嵌套空标签构成的占位空行
- 相邻重复行、全文重复行、重复段落处理
- 异常符号行、重复短页眉页脚、OCR 占位符处理
- 英文断行连字符修复、段内强制换行重排、段首缩进整理
- 多语言正则规则库、自定义规则、规则测试；自定义规则编辑窗口使用可滚动表单和固定保存／取消底栏，在 Windows 高缩放下也不会隐藏按钮
- 保存正则或大模型规则库后，当前文件、处理输入、当前结果和真实行号会立即恢复，不再出现编辑区空白
- 人工“查找”“查找全部”“替换下一个”“全部替换”和整理结果手动编辑；操作结束后显示匹配数或替换数，并可在编辑器中高亮匹配位置

### 编码转换

转码命令与规则整理完全分离。输出编码默认是 UTF-8；左侧输出面板、菜单和右键菜单均可转码当前、选中或全部文件。转码不会触发文本降噪；命令先校验当前工作文本能否按目标编码严格写出并登记待保存编码，只有随后执行保存命令才生成文件。可选择：

- UTF-8 / UTF-8 with BOM
- GB18030 / GBK / Big5
- UTF-16 / UTF-16 LE / UTF-16 BE
- UTF-32 / UTF-32 LE / UTF-32 BE
- Shift-JIS / CP949 / CP1252 / Latin-1 / ASCII
- LF / CRLF / CR 换行格式

若自动检测对极短文本给出较低可信度，可在“工具”或文件队列右键菜单中选择“按指定编码重新读取当前文件”，在随系统缩放的下拉窗口中选择编码，再执行整理或转码。

### 大模型辅助

大模型功能默认关闭，可在“设置 > 大模型”中选择 OpenAI / ChatGPT 或 DeepSeek，并分别配置 API 密钥和模型。

每次发送前先执行本地预检：任务必须能够表示为有界的精确片段编辑，文件必须非空，单片正文上限不得低于安全下限。翻译、总结、自由改写、扩写或内容生成、需要联网或外部事实的任务，以及 OCR、网页抓取和元信息提取会在发送任何文本前被拒绝。批量命令始终按文件顺序逐份处理，不会把多份文档合并到一次请求中。

超大文件不再因超过“单文件字符上限”而被整体拒绝。软件会完整覆盖当前工作文本，按逻辑行建立互不重叠的可编辑核心，并为相邻片段附加少量只读上下文。默认配置最多 24,000 个正文字符，自动整理会按任务密度使用更保守的有效片段（自然语言规则默认不超过 12,000 字符），上下各参考 2 行；设置中的“每个大模型片段的最大正文字数”和“只读上下文重叠行数”可以调整。压缩 HTML、JSON 等单行本身超过上限时，软件会在同一真实行内按字符位置继续分段，不丢弃任何正文。

每个片段在本机都有片段编号、短指纹、可见行范围和互不重叠的可编辑范围；超长单行还记录可编辑核心的起止列。这些传输身份不再要求大模型抄写。大模型只返回有问题的原子项目，包括操作类型、逐字原文、替换文本、行号提示、理由和置信度，不得回传完整改写文本或未变化行。独立问题即使位于同一行也必须分项；只有不可分割的段落或换行问题才允许跨行。

返回后，本机首先把响应绑定到发出该请求的真实片段，再用逐字原文搜索可编辑核心并重新计算稳定项目编号、短指纹、真实行号、全局出现序号和绝对字符位置。模型把全局行号误写成片段内行号、抄错编号／指纹或给错出现序号时，只要逐字原文在该片段中能够唯一定位，软件会安全修复定位而不是丢弃建议；原文不存在、只落在只读重叠区或出现多次且行号提示仍无法确定唯一位置时继续关闭式拒绝。自动整理还要经过无损及规则范围校验；多项修改按原始绝对位置从后向前应用，校对窗口则在用户逐条同意后更新后续位置。

| 命令 | 输入 | 处理方式 |
| --- | --- | --- |
| 整理当前/选中/全部（大模型） | 当前工作文本 | 大模型提出精确编辑操作，程序只自动执行通过安全校验的操作 |
| 大模型校对当前文件 | 当前工作文本 | 大模型提供建议，用户在独立窗口逐条或批量同意、拒绝 |
| 大模型自然语言规则安全整理 | 当前或选中文本 | 一次点击按顺序独立执行每条已选规则，逐层叠加，并仅自动执行通过本机安全校验的编辑 |
| 大模型自然语言规则校对 | 当前文本 | 一次点击逐条请求所有已选规则，合并并去重建议，再由用户逐条或批量决定 |
| 大模型生成正则规则 | 用户需求及可选的指定文件 | 返回 Python `re` 结构化规则，本机编译校验后由用户编辑确认 |

大模型校对窗口提供“同意”“拒绝”“全部同意”“全部拒绝”。每行是一项原子建议，并显示所涉及的当前结果行号（跨行建议显示多个行号）、原文片段、建议片段、理由、状态和差异。双击建议只会返回主窗口并定位、高亮对应行，不会同意修改；无法在当前文本中精确定位的建议会标记为“无法定位”，不会强制应用。一次校对会话中已同意的修改作为一个历史项，可通过编辑菜单或整理日志撤回。

执行大模型自然语言规则时，启用规则是完整且排他的任务说明，不再附加通用“去噪／删除广告／清除乱码”目标。多条规则不再依赖模型一次读完一个规则列表：软件在同一任务内按界面顺序逐条请求，每条规则只使用上一条完成后的当前结果，并独立执行范围校验；任一自动整理规则失败时，该文件整体回到本次任务开始前的状态，不留下只完成前几条规则的半成品。校对模式针对同一当前文本逐条请求规则，并按精确位置和替换内容去重。

若规则没有明确要求删除，本机范围校验会拒绝空替换、删除和“噪声移除”建议；“全大写词转首字母大写”一类规则还会核对替换结果是否严格等于指定字形转换。复杂编辑响应可使用大小写转换、精确替换、锚点插入、有界删除、重排或复合修改类型。自动模式只直接接受可由本机确定性验证的大小写转换，以及规则中用引号明确写出的“原文 → 新文”、删除目标或锚点插入；其余词义修改保留在人工校对窗口，避免以“兼容更多操作”为由放宽幻觉防线。

大模型自动整理不是让模型自由重写全文。通用自动整理只接受空白、段落、标点、完全重复片段删除和纯符号噪声删除；自然语言规则还可描述大小写转换、精确替换、锚点插入、有界删除、重排和复合修改。程序会再次检查逐字原文、出现次数、字符序列、规则范围和操作类型；大小写以外的词汇性自动修改必须由规则用引号明确给出源／目标关系，否则只进入人工校对。

自动整理按钮使用深红色警示样式。即使程序实施本地安全校验，自然语言规则写得过宽仍可能误删作者、来源或有意义的正文；执行前会再次警告，删除类需求优先使用“校对当前文件”，并应逐项核验。

大模型命令会明确提示其输入是“当前结果（最新工作文本）”，并在发送前显示文件数、总片段数、最大文件片段数和单片上限。状态栏按“文件／片段”显示总体 API 进度。单片请求失败、超时、空响应、截断、结构错误、建议无法精确定位以及确实没有建议会分别处理。服务商返回截断、JSON 外包装、结构验证失败或“修改过多”时，软件会丢弃该次不完整响应，自动缩小片段并重新覆盖全文；自动整理仍采用关闭式失败策略，只要最终有某个片段请求失败，整份文件就不应用部分结果。设置中可调整单次请求超时、服务商重试次数和自适应分片。

如果在校对请求返回前手动改变了目标文件的当前结果，软件不会把针对旧状态的建议套到新文本上，而会提示用户对最新结果重新校对。

涉及错字、词句或其它语义层面的修改只会进入“大模型校对建议”，不会自动写入，必须由用户逐条确认。这个设计把自动阶段的词汇性增删约束为零，同时保留人工审阅能力。模型输出本身仍不应被视为绝对正确，研究用途应保留原文和日志。

OpenAI 路径使用 Responses API 与只包含原子编辑内容的 Structured Outputs；DeepSeek Pro／Flash 路径优先使用同样精简的 `strict: true` JSON Schema 强制函数工具。模型不再负责生成或抄写片段编号、短指纹和稳定项目编号，从源头减少 DeepSeek 与部分 GPT 模型的格式错误。若 DeepSeek 接口明确不支持严格工具，则自动退回官方 JSON Output，并兼容 `replace`、`edit`、`spacing`、`line_break`、`capitalize`、`insert`、`remove` 等标签，及 `edits`／`changes`／`suggestions` 根字段、数字字符串、驼峰字段、`before/after/op` 别名、操作数组和多层嵌套子操作。嵌套项目递归拆分并逐项验证；真实请求上下文在本机绑定，坏项目不会使有效兄弟项目报废。两条服务商路径最终都进入相同的精确原文定位、歧义拒绝和编辑安全校验。默认模型分别为 `gpt-5.4-mini` 和 `deepseek-v4-flash`，均可在设置中修改。

自然语言规则只需描述“文本中什么内容要如何修改以及哪些内容必须保留”，不必写“生成一条建议”“返回项目编号”或其它输出协议；校对／自动整理方式由所点击的按钮决定。预检器会继续拒绝“生成文章、生成正文”等内容创作任务，但不会再把“为每处问题生成一条校对建议”误判为内容生成。

为减少流量，ClearLens 对每个片段只进行一次扫描，并要求只输出存在问题的原子差异；不会先发送全文做“问题检索”，再把同一正文发送第二次。固定任务协议和规则位于提示前部，变化的片段正文位于末尾，以满足服务商提示缓存对相同前缀的要求；缓存可降低符合条件请求的处理延迟与费用，但请求正文仍须发送。软件也不对待校对正文执行生成式摘要或激进 Token 删除：此类压缩虽然可能进一步节省输入量，却可能删掉正是需要发现的低频错误，不符合无损语料整理的目标。

### 大模型文本处理设计依据

- Liu et al.（2024）的 *Lost in the Middle* 发现长上下文中的信息位置会显著影响模型利用效果，因此“上下文窗口装得下”不等于可靠完整检查；ClearLens 选择逐片完整覆盖，而不是一次提交超长全文。[论文](https://aclanthology.org/2024.tacl-1.9/)
- Jiang et al.（2024）的 LongLLMLingua 指出长上下文同时带来成本、性能下降与位置偏差；Pan et al.（2024）的 LLMLingua-2 强调压缩的忠实性。ClearLens 借鉴其预算控制思想，但为保证待校对证据不被删除，不在正文上启用自动语义压缩。[LongLLMLingua](https://aclanthology.org/2024.acl-long.91/)；[LLMLingua-2](https://aclanthology.org/2024.findings-acl.57/)
- CoEdIT 与多语扩展 mEdIT 表明，明确、任务化的自然语言编辑指令适合文本编辑；ClearLens 进一步把复合结果拆成可定位、可拒绝、可撤回的原子修改项。[CoEdIT](https://aclanthology.org/2023.findings-emnlp.350/)；[mEdIT](https://aclanthology.org/2024.naacl-long.56/)
- OpenAI Structured Outputs 使用 JSON Schema 约束返回结构；提示缓存要求重复的静态内容位于精确相同的前缀位置。ClearLens 的 OpenAI 路径使用 Pydantic 结构化输出并设置 `store=False`，同时将固定协议置前、片段正文置后。[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)；[Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching)
- DeepSeek 官方说明 JSON Output 保证合法 JSON，但仍须在提示中给出格式并合理设置输出上限；当前 API 还提供带 `strict: true` JSON Schema 的函数工具。ClearLens 因此优先使用严格工具，明确不支持时才退回 JSON Output，并始终在本机逐项验证。[DeepSeek JSON Output](https://api-docs.deepseek.com/zh-cn/guides/json_mode)；[DeepSeek 对话补全 API](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion)

API 密钥只在当前会话或本机用户设置文件中使用，可在大模型设置中单独清除。密钥不会写入整理方案，也不会随方案导出。

## 推荐流程

1. 导入文件或文件夹。
2. 在左侧选择确定性整理功能、正则规则和可选的大模型自然语言规则。
3. 需要复用参数时，在“设置”菜单保存或导入整理方案。
4. 点击“预览效果”，检查前后对照与逐行差异表；双击差异行可定位并高亮原文。
5. 执行“整理当前（规则）”“整理选中（规则）”或“整理全部（规则）”。之后的每项规则、大模型或人工编辑都会继续作用于当前结果；大模型工具栏采用相同范围命名，例如“整理选中（大模型）”。
6. 对复杂文本执行大模型校对，或一次选择多条自然语言规则；先阅读任务与片段预算预检，再逐条或批量决定建议。批量任务会逐文件处理，每份文件内再逐规则、逐片段依次发送。
7. 需要纯编码转换时执行“转码当前／选中／全部”命令；转码状态同样可以继续叠加其它整理。
8. 确认结果后执行“保存”“另存为”或“全部保存”，再导出整理日志并保留原始文本。

## 安装与运行

推荐 Python 3.10 或更高版本。

```bash
python -m pip install -r requirements.txt
python main.py
```

Windows 也可以运行：

```text
run_clearlens.bat
```

OpenAI API 密钥可以在软件设置中输入，也可以使用环境变量：

```bat
set OPENAI_API_KEY=your_api_key
```

DeepSeek API 密钥也可以使用环境变量：

```bat
set DEEPSEEK_API_KEY=your_api_key
```

若不勾选“将 API 密钥保存在本机用户设置中”，密钥只在当前软件会话中使用。

## Windows 打包

```text
build_clearlens.bat
```

脚本只使用项目目录下的 `virtual_env`，并生成 PyInstaller `onedir` 发布目录：

```text
dist\BFSU_ClearLens\
  BFSU_ClearLens.exe
  _internal\                 Python 与第三方运行依赖
  assets\                    图标与图片
  config\                    默认设置与内置正则规则
  samples\                   示例文本
  README.md
  technical_readme.md
  RELEASE_NOTES.md
  requirements.txt
```

`assets`、`config`、`samples` 和文档均与 EXE 同级；不会作为应用资源写入 `_internal`。脚本完成后会检查上述目录和必要文件，缺失时构建失败。

发布程序使用 CustomTkinter 5.2.2 统一界面组件和 Windows 高 DPI 自动缩放，不再依赖 `tkinter-unblur`，也不再嵌入项目自定义 DPI 清单。原生 Treeview 数据表由 ClearLens 的 DPI 适配层根据所在窗口的有效 DPI 重算字体、行高、表头和列宽。Windows 原生菜单与文件选择窗口继续保留，`tkinterdnd2` 继续提供文件／文件夹拖放。软件不叠加全局界面缩放设置，A−／A+ 仅调整编辑器文字。

## English Summary

**BFSU ClearLens** is the text organization and deterministic cleaning application in the BFSU LexiScope framework. Its CustomTkinter interface follows Windows display scaling, while retained Treeview data tables use a per-window DPI adapter. Every rule, LLM, transcode, and manual edit uses the latest working text, while only explicit Save, Save As, or Save All commands write result files. It supports responsive background import, compact long-line HTML previews, one-task-at-a-time interface locking with cancellation, numbered queues, a clean-workspace command, direct output-folder access, Find/Find All/Replace counts, current/selected/all rule and LLM scopes, ratio-preserving split panes, unsaved-exit checks, encoding conversion, line-numbered editors, timestamped logs, 50-step undo/redo history, regex rules, guarded LLM cleaning, and individual or bulk review decisions. LLM preflight rejects unsuitable generative or external-knowledge tasks and oversized files before transmission; batch LLM jobs send one document per sequential request.

ClearLens imports text and exports text. It does not perform OCR, web crawling, or metadata extraction.
