## v1.5.11 预览稳定、窗口图标与大模型完整性保障

- 修复点击“预览效果”后，右侧“当前／预览结果（可编辑）”短暂显示结果、随后又被文件选择刷新覆盖为未编辑文本的问题。预览现在保存与当前文件及源文本绑定的显示快照；右侧结果仍可编辑，只有用户切换文件、实际修改文本或执行新任务时快照才失效。
- “前后对照”页移除始终占位的空提示栏。仅在显示流畅片段提示时临时展开，因此原文和结果编辑区更贴近选项卡标签，并继续保留可拖动比例分隔。
- 所有继承统一子窗口基类的窗口在创建、空闲映射和首次显示时重复应用软件 PNG/ICO 主图标，解决 Windows 与 CustomTkinter 在窗口映射后恢复通用图标的问题。
- 新增任务看门狗和大模型活动状态。状态栏持续显示当前片段、请求尝试、等待时长、单次超时阈值、响应已收到、本机校验和自适应重试；界面始终保持响应，并明确保留“中止任务”。
- OpenAI 与 DeepSeek 请求统一支持可配置的单次超时和服务商重试次数；超时与一般网络错误分开报告。设置新增“单次请求超时”“服务商自动重试次数”和“响应不兼容时自适应缩小片段”。
- 大模型修改数组上限由 500 提升至 5,000。DeepSeek 兼容解析可从说明文字或 Markdown 围栏中提取一份完整 JSON，但不会修补真实截断的数据。
- 自然语言规则、通用校对和自动整理根据任务密度使用更保守的有效片段。遇到输出截断、空响应、JSON／结构验证失败、没有有效项目或 `too many edits` 时，软件丢弃该次不完整结果，把片段缩小后重新完整覆盖原文，最多进行三级自适应请求；最终失败仍保持文件级事务回滚，不写入半截结果。
- 默认大模型配置调整为每片最多 24,000 字符、最大输出 16,000 tokens、单次超时 180 秒、服务商重试 2 次并启用自适应分片；已有用户设置仍会保留，但自适应任务上限会主动降低高密度规则的实际片段大小。
- 新增预览快照、等待状态、图标重映射、超时分类、500 条以上密集编辑、JSON 外包装和自适应重试回归测试。

## v1.5.10 大模型请求上下文绑定与可靠定位

- 修复 DeepSeek 及部分 GPT 模型已经返回正确逐字原文和修改内容，却因抄错片段编号、短指纹、全局行号或出现序号而被本机整批拒绝的问题。
- OpenAI Structured Outputs 与 DeepSeek 严格函数工具改用精简服务商模式：模型只返回操作类型、逐字原文、替换文本、行号提示、出现提示、理由和置信度；稳定项目编号、片段身份、短指纹、真实行号、全局出现序号和绝对字符位置均由软件掌握。
- 每条响应先绑定到产生它的真实请求片段。本机会在可编辑核心中逐字搜索原文：唯一命中时自动修正错误行号、编号和出现序号；多处命中时用全局行号提示或常见的“片段内行号”解释尝试唯一定位；仍有歧义、原文不存在或只落在只读重叠区时继续拒绝。
- DeepSeek JSON 回退允许真实请求上下文补齐服务商省略的传输身份和定位提示；只有操作被明确标为删除时才允许把缺失的替换字段解释为空，避免把不完整替换误变成删除。
- 拒绝原因拆分为“原文不存在”“多处歧义”“只读重叠”“重复项目”和一般无效定位；安全修复的项目只写入日志，不再阻止校对窗口打开。
- 修复自然语言预检把“每个问题生成一条建议”中的“生成”误判为内容创作的问题；“生成文章／正文／内容”等真正生成式任务仍会在发送前拦截。
- 新增服务商最小模式、请求上下文绑定、错误元数据修复、歧义关闭式拒绝、缺失替换保护和预检误判测试；完整回归测试现为 106 项。

## v1.5.9 预览基线、多规则完整执行与复杂编辑兼容

- 修复勾选本地整理功能后，“预览效果”在启用任意正则规则时可能看不到变化的问题。预览左栏现在始终是逐字不变的当前工作文本，右栏是本地选项、正则规则及可选大模型自然语言规则的完整结果，不再用本地整理后的中间状态抵消差异。
- 已勾选大模型自然语言规则可进入“预览效果”：软件先执行任务预检和发送确认，再按规则顺序生成仅用于显示的结果；预览不会写回当前工作文本，也不会保存到磁盘。通用大模型校对仍进入人工建议窗口，因为用户作出同意／拒绝决定前不存在唯一结果文本。
- 多条自然语言规则从“依赖模型一次遵循整个列表”改为“一次点击、逐条规则、顺序叠加”。每条规则独立请求、独立范围校验，并以上一条完成后的结果为输入；任何一条自动整理规则失败时，整份文件保持本任务开始前的状态，不留下只执行首条或前几条规则的半成品。
- 多规则校对逐条请求同一份当前文本，并按精确位置、原文和替换内容合并去重；某条大小写或删除规则的特殊约束不再误伤其它规则的合法建议。
- 结构化编辑类型扩展为大小写转换、精确替换、锚点插入、有界删除、重排和复合修改。自动模式仍关闭式校验：大小写操作必须保留大小写折叠后的字符及全部非字母字符；词义型替换、删除和插入只有在规则中使用引号明确写出源／目标或锚点关系时才可自动应用，其余项目只进入人工校对。
- DeepSeek 兼容解析新增 `edits/changes/suggestions/operations/items` 根字段、数值字符串、大小写不一致的编号／指纹、驼峰字段、`before/after/op` 等常见别名、操作数组以及多层嵌套子操作。嵌套修改会递归拆成原子项逐条校验；仍不会虚构片段编号、来源指纹、行号或原文。
- 新增预览基线、多规则顺序叠加、失败事务回滚、多规则校对去重、复杂类型规范化、显式替换安全校验、别名兼容、递归嵌套操作拆分及发布连线测试；完整测试套件现为 101 项。

## v1.5.8 DeepSeek Pro 严格结构与逐条兼容解析

- 修复 DeepSeek Pro 返回 `operation: "replace"` 时，Pydantic 因枚举不匹配而丢弃整批校对建议的问题。该错误发生在服务商输出类型标签，不是附件文本或参考文献数量导致，也不表示正文没有发送。
- DeepSeek 路径优先使用带 `strict: true` JSON Schema 的强制函数工具调用，从服务端约束项目编号、片段编号、短指纹、真实行号、操作类型、精确原文和替换内容。
- 当前接口明确不支持严格工具调用时，自动退回官方 `json_object` 模式，并在本批次缓存能力结果，后续文件片段不再重复失败探测；退回结果经过独立兼容层，支持 JSON 代码围栏、`replace/edit/spacing/line_break` 等常见别名、`line` 简写和少量字段别名。
- 兼容层逐项解析：坏项目单独丢弃，有效项目继续进入校对窗口；若全部项目缺少安全定位信息，则整片失败且不应用任何修改。片段指纹、真实行号、逐字原文、出现序号和重叠归属校验保持不变。
- 使用用户提供的两条参考文献英文文本确认正文为单一片段，并新增 DeepSeek 严格工具、JSON 回退、`replace` 归一化、混合好坏项目和全部无效关闭式失败测试。

## v1.5.7 行索引原子建议与超大文件大模型分块

- 大模型校对、通用整理和自然语言规则整理统一改为原子编辑协议：每个独立问题单独返回，包含项目编号、片段编号、短指纹、起止行号、逐字原文、替换文本、类型、理由与置信度；不再允许用一条建议合并远距离或无关修改。
- 超过单次请求容量的文件不再整体拒绝。软件按逻辑行生成完整覆盖且互不重叠的可编辑核心，相邻片段只附带少量只读上下文；压缩 HTML／JSON 的极端单行会继续按字符位置分段。
- 默认单片正文上限为 30,000 字符、只读上下文为 2 行；上下文字符量另有硬限制。使用用户提供的约 72.4 万字符 Yahoo HTML 验证时生成 39 个片段，完整覆盖全部正文，重叠传输开销约 3.74%。
- 模型只返回有问题的行或片段，不返回完整改写文本和未变化行。固定协议位于提示前部、变化正文位于末尾，满足 OpenAI 提示缓存对相同前缀的要求；缓存可降低符合条件请求的处理延迟与费用，但正文仍须发送。为避免漏掉低频错误，不对待校对正文执行生成式摘要或激进 Token 压缩。
- 本机新增唯一项目编号、片段编号、短指纹、真实行范围、超长单行可编辑列边界、精确原文、片段内出现序号和重叠归属校验。直接整理从后向前应用绝对位置，人工校对在每次同意后更新后续位置，防止前项修改造成后项错位。
- 批处理继续逐文件顺序执行，状态栏进一步显示文件／片段进度。任一片段请求失败、截断或结构无效时，自动整理不会应用该文件的部分结果。
- 设置增加“只读上下文重叠行数”；原“单次请求最大字符数”更名为“每个大模型片段的最大正文字数”。README、技术说明、三种语言关于与提示同步更新，并补充长上下文、提示压缩、文本编辑及结构化输出文献依据。
